## 4. Mutation Architecture

The cloud mutation architecture strictly follows the unidirectional, domain-driven boundary specified in Section 6:

```
UI Interaction (Form Submit / Drag / Drop / Select)
       │
       ▼
Domain Command (TaskService / TreeService)
       │
       ▼
Tenant & Concurrency Guard (appState.activeOrganizationId, version counter)
       │
       ▼
Repository Boundary (TaskRepository / NodeRepository)
       │
       ▼
Supabase PostgREST Client (Bearer JWT token)
       │
       ▼
PostgreSQL Engine (RLS Policies & Definition Triggers: guard_task_write)
       │
       ▼
Authoritative DB Row (Canonical UUID & updated_at)
       │
       ▼
Read Model Projection Refetch (task_rollups view)
       │
       ▼
UI Snapshot Replacement & State Re-render
```

Direct, scattered Supabase calls in `js/core.js` were avoided. All handlers invoke `TaskService` or `TreeService`, which encapsulates validation, error formatting, race guards, and canonical view refetching.

## 5. Task Create

- **API Endpoint:** `POST /rest/v1/tasks`
- **Tenant Assignment:** Explicitly locked to `appState.activeOrganizationId`.
- **Node Assignment:** Must belong to the same organization and reside within the user's allowed scope. Cross-organization node assignment is immediately rejected by PostgreSQL composite foreign key `tasks_organization_id_node_id_fkey` (HTTP 409).
- **Assignee Assignment:** If assigned, must belong to `public.employees` of the same organization. Cross-organization assignee is rejected by trigger `guard_task_write` (HTTP 400).
- **Canonical Enums:** UI Vietnamese strings ("Chưa làm", "Khẩn cấp") are mapped bidirectional to DB canonical enums (`todo`, `urgent`).
- **Post-Mutation Consistency:** Directly after `POST`, `TaskService` refetches the row from `public.task_rollups` to guarantee computed fields (`actual_minutes`, `checklist_total`, `is_blocked`) match authoritative database state.

---

## 6. Task Edit

- **API Endpoint:** `PATCH /rest/v1/tasks?id=eq.{taskId}`
- **Minimal PATCH Payload:** The edit form constructs an exact delta payload containing only modified planning fields (`title`, `description`, `node_id`, `primary_assignee_id`, `priority`, `start_date`, `due_date`, `estimate_minutes`, `progress`).
- **Forbidden Overwrites:** Front-end never submits `id`, `organization_id`, or `created_by`. Attempting to tamper with `organization_id` is blocked by database trigger `guard_task_write` (`raise exception 'Cannot change organization_id of task'`).

---

## 7. Task Status / Kanban

- **Kanban Drag & Drop:** The Step 05 read-only gate was unblocked.
- **Workflow Pipeline:**
  1. Record previous card status.
  2. Apply optimistic visual feedback.
  3. Call `TaskService.updateStatus(taskId, status)`.
  4. If successful, commit authoritative canonical row from `task_rollups`.
  5. If rejected (e.g. network failure, RLS denied), revert visual position and display Vietnamese toast error.
- **Rapid Drag/Drop Protection:** Task generation versioning (`taskMutationVersions.set(taskId, generation)`) ensures out-of-order network responses from rapid moves are discarded.

## 8. Progress

- **Validation Bounds:** Client validation and database check constraint `tasks_progress_check` enforce `progress >= 0 AND progress <= 100`.
- **Constraint Test:** Submitting `progress = 105` returns HTTP 400 with check constraint violation.
- **Child Automation:** Local pseudo-checklist mutations are prevented from falsely manipulating cloud progress; checklist calculations remain untouched until Step 07.

## 9. Date / Timeline Mutations

- **Field Mapping:** `startDate` -> `start_date`, `dueDate` -> `due_date` in ISO format (`YYYY-MM-DD`).
- **Validation:** Ensures start date <= due date where both are specified.
- **Storage:** Persisted authoritatively to `public.tasks` columns `start_date` and `due_date`.

## 10. Archive / Delete Contract

- **Canonical Strategy:** Soft archive via `archived_at = now()`.
- **Active Task Query:** Authoritative query `GET /task_rollups?organization_id=eq.{orgId}&archived_at=is.null` automatically excludes archived tasks.
- **UI Behavior:** Archiving a task closes the detail drawer, unchecks selections, and triggers re-render without page reload.

## 11. Organization Node Create

- **API Endpoint:** `POST /rest/v1/organization_nodes`
- **Supported Node Types:** `department`, `project`, `team`, `folder`.
- **Strict Invariant B:** Creating `person` nodes is strictly blocked by client UI filtering and rejected by DB enum `node_type`.
- **Root Node Protection:** Creating a second `company` root node is strictly blocked (`NodeRepository` throws error if `type === 'company'`).
- **Closure Automation:** `organization_nodes_refresh_after_insert` database trigger automatically maintains `organization_node_closure`.

---

## 12. Node Update / Move

- **Rename / Update:** Minimal PATCH updates `name`, `description`, `capacity_hours_week`.
- **Move / Reparent:** Database closure tree trigger `organization_nodes_prevent_cycle` validates that moving a node into its own descendant is strictly prevented (HTTP 400).
- **Root Node Immutability:** Renaming root node is permitted only to authorized Owners; mutating root node `parent_id` or changing `type` away from `company` is blocked by DB trigger `validate_node_write`.

---

## 13. Role & Scope Enforcement

Verified against live remote PostgreSQL RLS:
- **Owner & Admin:** Full create, update, and soft archive rights within the organization.
- **Manager (In-Scope):** Can create and manage tasks within nodes assigned in `member_scopes` (HTTP 201 PASS).
- **Manager (Out-of-Scope):** Cannot create tasks in unassigned nodes (HTTP 400 / 403 DENIED).
- **Viewer:** Cannot create tasks (HTTP 400 DENIED) or nodes (HTTP 403 DENIED); cannot update tasks (0 rows updated).
- **Cross-Tenant Attack:** User A attempting to update or read Org B tasks receives 0 rows under RLS.

---

## 14. Field-Level Authorization

- **Member Restrictions:** Enforced at the database trigger level by `guard_task_write` (migration lines 1148–1165):
  ```sql
  if v_role = 'member' then
    if (new.title is distinct from old.title or
        new.description is distinct from old.description or
        new.node_id is distinct from old.node_id or
        new.priority is distinct from old.priority or
        new.start_date is distinct from old.start_date or
        new.due_date is distinct from old.due_date or
        new.estimate_minutes is distinct from old.estimate_minutes or
        new.tags is distinct from old.tags) then
      raise exception 'Member can only update status/progress on the task row';
    end if;
  end if;
  ```
- **Live Verification:** Member mutating `status` and `progress` succeeds (HTTP 200); Member attempting to alter `title` is immediately aborted by PostgreSQL (HTTP 400: `Member can only update status/progress on the task row`).

## 15. Concurrency / Conflict Handling

- **Optimistic Concurrency Control (OCC):** `TaskRepository.updateTask` supports `expectedUpdatedAt` parameter. When provided, updates are scoped with `.eq('updated_at', expectedUpdatedAt)`.
- **Zero Rows Detection:** If another user modified the row, zero rows are updated, prompting automatic refetch of the canonical state and user notification: *"Dữ liệu đã được thay đổi ở nơi khác. Đã tải lại phiên bản mới nhất."*

---

## 16. Workspace-Switch Race Protection

- **Tenant State Guard:** In `TaskService` and `TreeService`, the `activeOrganizationId` is captured prior to dispatching network mutations.
- **Commit Guard:** Before applying response data to application state, `appState.activeOrganizationId` is rechecked. If the user switched workspaces while the mutation was in-flight, the response is discarded without contaminating the UI of the newly selected tenant.

---

## 17. Error Handling

Supabase and PostgreSQL error codes are mapped into user-friendly Vietnamese notifications:
- **Permission / RLS Denied (42501):** *"Bạn không có quyền thực hiện thao tác này."*
- **Foreign Key / Relation Conflict (23503, 23505):** *"Dữ liệu liên quan không còn hợp lệ hoặc trùng lặp."*
- **Check Constraint (23514):** *"Giá trị không hợp lệ (ví dụ tiến độ phải từ 0 đến 100%)."*
- **Network Outage:** *"Không thể kết nối máy chủ. Vui lòng kiểm tra mạng."*
- Raw SQL stack traces and sensitive connection tokens are never exposed to the UI.
